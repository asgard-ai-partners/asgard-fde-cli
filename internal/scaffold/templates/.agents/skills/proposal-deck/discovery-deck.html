從一份真的拿去開會的訪談 deck 抽出來,客戶名詞已中性化,問句用字未改。

頁面結構

情境頁:客戶原文的流程 + 他自己的兩欄清單,不問任何問題

子題頁:左欄藍字問句,右欄產出,一個子題一頁

藍字就是問句本身,灰字是補充,沒補充就空著

沒有分類標籤,沒有結語,沒有講稿

產出欄的最後一條一定是失敗行為

查不到就說查不到,不會猜一筆

連不上就說連不上,不會拿昨天的數字給你

送不出去它就說送不出去,不會說已經開好了

這一條在客服場景比任何能力描述都有說服力

交付

這一輪 Asgard 會交付什麼

無論三個情境最後採用幾個,以下三項在測試期結束時一併交付。

Asgard AI Workspace平台上的專屬工作空間。三個情境的設定都在裡面,管理人員登入後看得到內容、改得動設定,也看得到用量與計費
Dev Projects一個情境一個獨立專案,彼此不共用資料與權限。可以只讓其中一個先上線,不必等三個都做完
Infra as Code 儲存庫整套設定以程式碼形式交付:每一個查詢、每一份對照、每一個需要人工確認的動作都在裡面。可以審查、可以比對版本、可以重新部署
